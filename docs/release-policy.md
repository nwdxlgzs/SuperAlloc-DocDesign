# 版本、兼容与发布门槛

状态：发布规则设计，无已发布版本、稳定二进制或兼容文件。本次文档可以完整给出字节规格候选，**设计候选完成**与**发布格式冻结**是两个不同门槛。

## 1. 五种版本分别管理

| 版本域 | 改变什么 | 兼容处理 |
| --- | --- | --- |
| 文档基线 | 设计说明、流程、证据与更正 | 记录ADR、日期和相关任务；不冒称已有代码版本 |
| 公共ABI | 符号、调用约定、字段宽度/偏移、状态及输出合同 | 已发布编号不复用；不兼容变更升major并显式拒绝不匹配 |
| defaults profile | 自动额度公式、默认策略 | 调用方明确版本；库不能无声用新公式解释旧profile |
| store format | super/checkpoint/WAL记录、必要特性和恢复语义 | 不兼容明确拒绝；未知required feature不能跳过 |
| 应用payload | 业务对象、引用和schema | 由应用管理；allocator格式兼容不代表payload兼容 |

结构扩展必须先通过struct_size/abi_version及输出长度合同；保留字段为0并验证。公开C ABI不能依赖C++ enum/bool、native long或编译器私有类布局。固定宽结构与含native pointer参数结构分别验证32/64位；实现内部S-01布局不是用户可持久化ABI。

格式major/minor候选及具体兼容比较由[持久格式](persistent-format.md)规定。版本字段存在不意味着任意minor自动兼容；未知record长度/必须理解的功能若可能改变所有权或恢复顺序，必须拒绝。首版不自动迁移、不原位升级、不用关闭未知校验来“抢救”打开。

## 2. 从文档到冻结

| 门槛 | 输入 | 退出证据 |
| --- | --- | --- |
| 设计候选完成 | D/S任务、交叉审查 | 接口字段、流程、公式、错误与恢复无已知矛盾；所有假设可追踪 |
| ABI候选验证 | I-01/I-02/I-03、S-04 | C17/C++20、平台布局、导出/调用约定、native atomic与size边界实测 |
| 格式候选验证 | I-10A、S-05、可控文件模型 | 明确持久链路；字段编码、CRC、WAL尾判定、双super切换与崩溃证据 |
| 正式兼容冻结 | I-10/I-11/I-12、I-14 | 正式候选文件跨同几何重开；已支持feature矩阵；坏格式拒绝；兼容fixture入档 |
| 发布 | 全部适用I/V门槛 | 支持平台表、可运行示例、已知限制、包与证据、性能适用范围 |

冻结之前用于spike的文件标记为实验，不能混入正式兼容fixture；更改候选布局要同步文档和测试，允许重新生成实验文件。冻结之后不能为修复实现随意改变旧格式含义；需要新的版本或保持原合同的兼容修正。

## 3. 发布内容

发布包计划包括公共头文件、适用静态/共享库、构建与接入说明、能力矩阵、六类生命周期示例、版本/格式/defaults标识及测试/基准报告链接。每个产物可追溯源码版本和工具链。发布前由维护者确定项目许可证、依赖许可与分发方式；当前不擅自选择许可证或宣称已有授权文件。

平台支持表按OS版本、ABI、P、存储文件系统和能力分别列状态：支持且验证、实验、不可用、未测。所有四平台目标都在计划中；缺少真机验证的目标不改名为支持以满足宣传。4TiB说明为64位设计上限及实测设备reserve能力，不承诺所有设备能创建。

发布说明以用户行为变化、修复影响、兼容要求、资源/性能代价和迁移步骤为主。无实际测量时只描述设计目标；“更快”必须链接可复现实验，能力不等价的对手不用于胜率统计。

## 4. 回归与变更控制

所有权、安全释放、隔离与持久提交正确性为硬门槛。性能在固定稳定基线后采用>5%吞吐退化、>10%p99上升、>5%峰值backend资源增长且超出噪声的审查阈值；解释和接受的取舍写ADR，不能用某场景收益抹去其他场景失败。

公开合同变动先更新API/ABI、ADR、验证和接入指导；预算变动同步S-01/S-02算例；disk变动同步解析器边界、重放状态机和fixture策略。仅文档语病修正不要求重跑完整硬件矩阵，影响机制时才扩展验证。

## 5. 升级、回退和损坏处理

升级前在业务一致性点制作完整备份并验证可打开性。新库先只读校验格式/几何，不能看到旧版本便自动改写。若格式相同且能力经过验证，正常close后可由兼容库重开；若新库已写入旧库不理解的feature，回退必须使用兼容备份或离线转换。

离线迁移未来方案为：只读验证源 → 创建独立目标 → 应用枚举并转换对象与引用 → persist/root/checkpoint → 验证完整性 → 应用切换主文件身份。目录offset与allocation ID可以改变，不能复制旧handle后声称有效。首版没有通用payload迁移工具，跨ABI/页几何拒绝属于已确定边界。

损坏store保持不写入，保留原件和诊断副本；修复实验在副本上进行，不在open内部猜测丢弃中间日志。进程kill恢复通过不提升为断电保证；公开持久性范围始终限定于已验证的OS/FS/设备与屏障合同。
